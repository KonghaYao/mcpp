如何设计这个系统

01 · Product thesis

不是“插件商店”，而是 AI 工作能力的装配台。

用户不需要理解模型和协议，只需要回答两个问题：找谁来做，以及允许它连接哪些工作数据与工具。

02 · Information architecture

按用户意图组织，而非技术类型

A
发现

精选场景建立认知，分类与搜索承接明确需求。

B
判断

卡片只回答能力、来源与适用场景；详细权限进入详情页。

C
装配

添加后进入工作台，在真实任务中组合并运行。

03 · Core model

三个核心对象

Expert
身份、能力边界、作者、推荐组合
Connector
授权、Tools、Resources、健康状态
Workspace
用户安装项、组合关系与执行记录

04 · Key journeys

先完成四条闭环，再扩展功能

J01场景 → 专家 → 添加 → 开始对话
J02搜索 → 连接器 → 授权 → 测试成功
J03专家详情 → 推荐连接器 → 装配工作台
J04运行失败 → 定位权限 → 修复并重试

05 · Component rules

专家卡

名称优先；来源建立信任；简介不超过两行；标签最多三个；添加按钮在 Hover 或键盘聚焦时出现。

连接器卡

Logo 是首要识别线索；描述强调用户能完成的动作，不罗列 API；安装后“+”变为“✓”。

筛选与搜索

全局搜索始终保留；分类只做高频入口；筛选结果即时反馈，并提供可恢复的空状态。

权限确认

授权前展示数据范围、可执行动作与提供方；高风险写操作必须二次确认，并留下审计记录。

06 · Visual system

密度规则

  • · 桌面容器上限 1280px，正文有效行宽不超过 72 字符。
  • · 市场列表桌面三列、平板两列、手机单列。
  • · 基础间距 4px；常用组合为 8 / 12 / 16 / 24 / 32。
  • · 首屏至少展示一排场景和两排能力卡。

颜色与层级

品牌色只用于链接、焦点与关键状态；连接器品牌色仅存在于 Logo 容器。

07 · Trust & safety

市场的信任成本高于普通应用商店

必须把“谁提供、读什么、写什么、何时调用”设计成一级信息。连接异常、授权过期、Tool 变更和危险操作都要有独立状态，不能只显示笼统的“失败”。

设计目标：让初次用户在 30 秒内理解三个能力层，在 2 分钟内完成第一次装配；让熟练用户不离开列表即可完成搜索、筛选和安装。
